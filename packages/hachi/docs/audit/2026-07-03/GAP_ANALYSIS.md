# Hachi — Competitive Strategy & Gap Analysis

_Prepared 2026-07-04. Ground truth: full codebase read + the 2026-07-03 production audit. Competitive claims independently verified against primary sources this session; every figure carries a source + date, and I flag what could not be confirmed._

---

## 1. Executive summary

Hachi is a genuinely well-engineered agent **engine** wrapped around a marketing story it does not yet deliver. The spine is real and rare: a ReAct loop with call-time permission gating, in-loop per-turn/per-session cost caps, a hardened loopback gateway (sha256 bearer, constant-time compare), a durable SQLite job queue, multi-provider routing, an eval-replay CI gate, and ~59k LOC behind **4,151 passing tests / 0 failures** (`docs/audit/2026-07-03/PRODUCTION_READINESS.md`). Almost nobody in this category has that discipline. But the same audit — reproduced first-hand — shows the **headline features are hollow at exactly the points the brand rests on**: automatic long-term memory is a silent no-op for every user (missing symbol `get_memory_vault`), the file-attachment tool group crashes on every call, the flagship "97.6% token savings" number measures a query that silently _fails_ (its Pass-2/3 are 13-token error strings) and the benchmark's own CI gate is red on the shipped corpus, ~85% of documented slash commands don't exist, "Notion/Slack via OAuth" is a facade whose tokens nothing consumes, and — most damning for a product whose tagline is _"enforced by code, not by vibes"_ — the two headline governance differentiators (skill-lint rejection, machine-checkable `::assertions`) are **honor-system**, with no enforcement point, and the web UI's approve/decline buttons are optimistic-only and never call the backend.

So the honest position: **Hachi has built the hard, unglamorous 20% that competitors skip (governed, tested, auditable internals) and skipped the glamorous, table-stakes 80% that competitors nail (memory that works, breadth, reliability, a benchmark that survives replication).** The founder's instinct about _where_ the market is going — control + visibility as the axis OpenClaw and Hermes leave open — is directionally right and now better-evidenced than when the thesis was written. But it is not yet a moat, it is being copied in real time (Hermes shipped memory-visibility on 2026-07-01; Claude Code already ships classifier-based action governance that is more advanced than Hachi's honor-system state), and it is undercut by Hachi's own claim-vs-code gap. The strategic task is not to invent a new thesis. It is to **make the current claims true, then convert "governance" from a copyable feature into a verifiable, user-owned substrate** before a better-funded competitor closes the window.

## 4. Must-have list (ranked) — table stakes; Hachi is not credible without these

1. **Automatic memory that actually works (audit C1).** _Who bounces:_ every user who says "remember this" or expects the advertised "you never need to say remember." Both direct rivals persist memory reliably; Hachi's silently writes nothing. This is the single most brand-damaging gap because _memory is the category's whole premise_ and Hachi's tagline sells "self-improvement." Fix the missing `get_memory_vault` and the `ANTHROPIC_API_KEY` gate that doubly-kills it for non-Anthropic users.
2. **Make governance _enforced_, not honor-system (audit M2).** _What breaks:_ the entire "enforced by code, not by vibes" positioning is currently false at its two headline points — lint never rejects a skill write, `::assertions` have no enforcement point, and the **web approve/decline buttons don't call the gateway** (optimistic-only). A competitor or auditor who checks will find the governance product doesn't govern. This is existential to the thesis; nothing else in the strategy survives if it's discovered.
3. **Fix or retire the 97.6% benchmark (audit C3/C4).** _What breaks:_ the marquee proof of the moat currently proves a query silently failed cheaply, and the CI gate is red on the shipped corpus. Publishing a number that dies on hostile replication is worse than publishing none — and the founder's own doc warns "fix → benchmark → tell." Pick a query that resolves to one real skill; regenerate frozen results in CI; correct the README badge.
4. **Working file/attachment tools (audit C2).** Crashes on every call. Basic agent competence.
5. **Docs = reality.** Implement or delete the ~11 non-existent slash commands (H4); fix the tier names (`lightning/guided/strict` → real `sandbox/guided/unrestricted`, H7); stop advertising "Notion/Slack via OAuth" when only Google uses it (H5). The first contributor who tests a README claim is your highest-signal skeptic.
6. **Be installable (audit H9, M13).** `pipx install hachi-og` 404s; `docker compose up` fails on a clean clone. The most prominent install path must work or the honest paths must lead.
7. **Enough channel breadth to live in.** OpenClaw has ~23, Hermes ~10; Hachi's transports are ~4–5 and shallow. You don't need 23, but a personal agent people _route their life through_ needs the few they actually use (WhatsApp/Telegram/Slack/email) to be real, not facades.

## 5. Good-to-have list — real differentiators, not urgent

- **A goals/Kanban autonomy board** (Hermes has one; it's a big part of why it _feels_ like a capable coworker). Hachi has the job queue and `/runs` plumbing to back one.
- **`.ogpack` marketplace with consent-sheets / scope-diff on install** — roadmapped; the structurally-correct answer to ClawHavoc. Good-to-have _as a marketplace_; the underlying scope-diff is a god-tier item (see §6).
- **Honcho-class user-modeling** — an editable _model of the user_, not just a fact vault. Hermes integrates Honcho today; Hachi's `user_profile` collection is a weaker version of the same idea.
- **Deeper integration reality** — turn the Notion/Slack OAuth facade into real token consumption; it's plumbing, not research.
- **Voice/realtime polish and a fleet/multi-agent UI** — the sub-agent engine exists; the surface doesn't.
- **Retention/prune sweeps and data-durability fixes** (audit H8/H3/M1) — not user-visible until they bite, but a "governed" product that leaks transcripts on delete and can self-wipe its secret store contradicts its own promise.

## 6. God-tier bets — category-defining, each tied to a falsifiable capability gap

Each is stated as a test no shipping product passes today.

- **G1 — The owned, tamper-evident flight recorder.** _Falsifiable test:_ can a user hand a third party a signed, complete, replayable record of **everything their agent did and why**, and have it independently attested? Today: **no one passes.** OpenClaw is opaque (the CVE let attackers modify the governance layer itself); Hermes memory was a "black box" until 2026-07-01 and even now the _timeline_ is a viewer, not an attestable log; Claude Code's logs are local/vendor. Hachi already emits typed runtime events and an `interaction_log` — it is one signed, append-only, exportable step from a capability nobody has shipped.
- **G2 — Provable blast-radius before install.** _Falsifiable test:_ can you install a third-party skill/pack and see a **provable upper bound** on what it can read, write, spend, and reach — _before_ it runs? No marketplace does this; ClawHavoc (824+ malicious skills shipping AMOS stealer) happened precisely because install = trust. Hachi's `.og` skills are typed, scoped, and permission-declarative — the one format in this space where a static "what could this touch" proof is even _possible_. This is the moat the founder is circling but hasn't named sharply.
- **G3 — A user-model you can correct and watch stick.** _Falsifiable test:_ can you open what the agent believes about you, edit a wrong belief, and verify the correction actually changed future behavior? Hermes only _started_ down this road with v0.18.0's `/journey`. Nobody has nailed "the agent was wrong about me and I fixed it." Hachi's structured `user_profile` (hard-capped, frozen in the system prompt) is a better substrate for this than a raw vector store — _if memory works at all_ (see must-have #1).
- **G4 — Approval at consequence boundaries, not action boundaries.** _Falsifiable test:_ does the agent batch its intent into a **reviewable plan with a blast-radius estimate** and interrupt you _only_ for the irreversible/expensive/external actions — instead of a firehose of "approve this file write"? Approval fatigue is the root cause of the whole OpenClaw disaster: 93.4% of instances ran with auth _off_ because friction pushed people to disable safety. The winning UX isn't more prompts; it's _fewer, higher-signal_ ones. No one has built this well.
- **G5 — Portable agent sovereignty.** _Falsifiable test:_ can you pick up your governed memory + skills + audit history as a provably-yours artifact and move it to another host? Everyone's memory is a lock-in silo. Hachi's file-based `.og` + local stores make anti-lock-in _shippable as a feature_ — and it's the deepest expression of the "sovereign" positioning the founder already claims.

The through-line: **G1–G5 are all the same bet — turn governance from prompts-and-logs into a verifiable, owned, portable trust substrate.** That is the version of the founder's thesis that a competitor _cannot_ copy in a month, because it compounds with the user's accumulated history.

## 7. First-principles notes

**Set the competitors aside. The underlying problem:** a person wants to delegate real work — work that touches money, private data, external services, and other people — to software that acts on their behalf _without them watching_. The obstacles, in order of how often they kill adoption: **reliability** (does it finish the task), **recall** (does it know me), **reach** (can it touch my systems), **trust** (will it do only what I'd want), **economy** (predictable cost). Notice governance is #4, not #1 — a point I'll return to.

**Assumptions every existing tool bakes in that a from-scratch design would question:**

- **"An agent is a chat loop."** Delegation isn't conversation; it's _managing an employee_ — assign, work asynchronously, report, review. The chat metaphor is wrong for autonomy. The right primitive is a **work inbox / queue**, which is why Hermes' Kanban resonates and why Hachi's chat-first surface undersells its own job queue.
- **"An agent is one monolithic thing with one permission set."** Trust decomposes by scope — you'd trust different "employees" with different reach. **Role-scoped sub-agents with per-role permission envelopes** is the more natural shape. Hachi _has_ this (`delegate_task`, role brains) and barely exploits it.
- **"A skill is text you load into context."** This is the assumption Hachi's `.og` format actually challenges — skill as a queryable, typed, versioned, scoped _graph_. It is Hachi's one genuinely novel, hard-to-copy bet, and the strategy under-sells it by burying it under a broken token-savings number.
- **"Memory is retrieval."** A personal agent doesn't primarily need a fact vector store; it needs an **editable, inspectable model of you** that you can correct — and _proof it's synced_. Hachi's is silently broken; the whole industry ships write-only memory nobody can audit.
- **"Governance is prompts, or after-the-fact logs."** First-principles, governance should be a layer the agent _physically cannot bypass_, and the human's interface to it should be an **inbox of consequential decisions**, not an approval firehose.

**Where the founder's thesis is right:** skill-as-typed-artifact is a real and defensible insight; governance-by-construction is the correct axis to attack the OpenClaw/Hermes flank; sovereign single-tenant is a real, underserved segment; and in-loop cost caps are genuinely rare and valuable (no direct competitor has them — OpenClaw's runaway-spend bugs are documented and unfixed at the design level).

**Where the founder's thesis is wrong or blind:**

- **The claim-vs-code gap is the actual product risk, and it's self-inflicted.** The README attacks Hermes for ungoverned learning and OpenClaw for exposure while Hachi's _own_ governance is honor-system and its memory is a no-op. You cannot win a trust argument from a product that doesn't yet do what it says. This is #1 by a wide margin.
- **Governance is a vitamin, not a painkiller, for most individuals** — felt only _after_ an incident. It's a genuine purchase criterion for the _burned_ and for _teams/enterprises_, which is a real wedge, but it is not a mass-market "can't stop using it" hook. Reliability and memory are the painkillers; governance is what keeps the _already-converted_ from leaving.
- **"We deliberately don't learn autonomously" reads as _less capable_, not _safer_, to most users.** Hermes shipping memory _visibility_ (v0.18.0) shows the market wants autonomy **and** control — not a choice between them. Positioning the _absence_ of a learning loop as a virtue cedes the capability frame. The right move is _governed autonomy_ (learn, but every learned change is versioned, diffable, and enforce-checked), not _no autonomy_.
- **The moat as framed is copyable and being copied.** More on this in the thesis test below.

### Stress-test 1 — "Harness quality matters more than model quality"

**Verdict: directionally true for agent products — but the evidence indicts Hachi's own execution.** The harness swing is large and real: the same base model scores **46% vs 80%** depending on scaffolding (Cursor's research, via [MindStudio](https://www.mindstudio.ai/blog/agent-harness-scaffolding-matters-more-than-model), 2026-05-18); independent reports show **42%→78%** and, per [Lee Hanchung](https://leehanchung.github.io/blogs/2026/05/08/hidden-technical-debt-agent-harness/) (2026-05-08), GPT-5.1 Codex at **20.2% vs 7.7%** under first- vs third-party harnesses. (The "~5%→30%" figure in Hachi's mental model is **not supported** by any source — use the real numbers above.) Both direct competitors are model-agnostic bets, confirming the industry believes it.

**Where it breaks down — and this is the important part for Hachi:**

1. **The model is the ceiling; the harness is the multiplier.** A great harness on a weak model still fails hard tasks. Harness amplifies capability, it can't exceed it.
2. **Harness ROI _falls_ as models improve.** As models self-correct, the value of retry/verification scaffolding erodes. Betting the company on scaffolding is betting against the base rate of model progress.
3. **"Harness" is an equivocation.** It bundles breadth + reliability + memory + governance. Users feel **breadth, reliability, and memory first**; governance last. Hachi invested in the governance slice and, per its own audit, **the reliability/memory slice is broken** (memory no-op, file tools crash, approvals don't fire). Taken seriously, the thesis says: _the harness quality that wins is the boring reliability you skipped._ The thesis is true, and it currently argues _against_ Hachi's execution priorities.

### Stress-test 2 — "Owner control + visibility/governance is a durable moat"

**Verdict: real and rising demand, but not durable as currently framed, and not yet real in the product.**

_Evidence the demand is real:_ Anthropic — the best-resourced player — treats admin-controlled agent governance as a **product requirement**, shipping six permission modes, a classifier-model "auto" mode that is _injection-hardened_ (tool results stripped from the classifier's view) and blocks the agent from tampering with its own oversight, plus enterprise lock-off of dangerous modes ([code.claude.com/docs/en/permission-modes](https://code.claude.com/docs/en/permission-modes)). Incidents manufacture demand continuously: Replit's DB deletion, OpenClaw's CVE-2026-25253, ClawHavoc.

_Evidence it is NOT durable as framed:_

- **This space copies features in weeks.** Hermes overtook OpenClaw by copying and extending (the learning loop), and even ships an official `hermes claw migrate` command to poach OpenClaw users' memory files directly. When the exact "black box" criticism landed, Hermes shipped memory _visibility_ (`/journey` timeline + memory graph) in a point release on **2026-07-01** — i.e., the visibility gap Hachi wants to own is _already closing at a competitor, in real time_.
- **A resourced incumbent already out-governs Hachi.** Claude Code's classifier auto-mode is _more advanced_ than Hachi's honor-system lint/assertions **today**. "We have approval prompts" is copyable in a sprint; Anthropic did it better first.
- **The moat doesn't exist even as claimed** — honor-system enforcement, web approvals that don't call the backend.

_What would make it durable (the pivot):_ stop selling _approval prompts_ and start selling a **verifiable, owned trust substrate** — every action, memory write, skill mutation, and dollar passes an _enforced_ policy-as-code gate and lands in a **signed, portable, replayable audit log the user owns and can attest to a third party** (§6, G1–G5). Copyable features aren't a moat; **accumulated governed history + provable ownership + switching cost** is closer to one. The durable claim is _"your agent's entire life is an auditable, versioned, portable, policy-enforced record you own"_ — which compounds over time and is painful to recreate elsewhere.

**One correction the founder should absorb:** three competitor claims in Hachi's own README/strategy docs don't survive verification, and shipping them weakens the trust pitch:

- "OpenClaw has no native memory / no selective loading" — **false.** OpenClaw has markdown memory _and_ semantic `memory_search`/hybrid retrieval. What it lacks is the _autonomous self-improvement loop_, not memory.
- "Hermes' Curator overwrites manual edits" — **overstated.** By design the Curator does **not** touch hand-written skills (`created_by: null`) and supports pinning; the real, filed pain ([#18373](https://github.com/NousResearch/hermes-agent/issues/18373)) is auto-_archiving_ user-created skills without a dry-run. The "dealbreaker for power users" quote has no primary source.
- "Hermes learning loop off by default" — **only the LLM consolidation sub-pass is off**; the background skill-creation review runs by default (~every 10 turns).
- _Holds up:_ the **"4 Critical + 9 High" Hermes audit is real** — it's literally the title of [issue #7826](https://github.com/NousResearch/hermes-agent/issues/7826) (Anic888, 2026-04-11, open, against v0.8.0). Attack from _verified_ facts (the CVE, ClawHavoc, #7826, raw `bash -c` default), not from the softer claims.

## 8. Positioning statement + top strategic bets

**Positioning (one sentence a stranger can repeat):**

> **Hachi is the self-hosted personal agent you can safely let off the leash: it does real work for you while every action, memory, and skill is enforced by policy in code and written to an audit trail you own — autonomy with a receipt.**

**Top 5 bets — in dependency order:**

1. **Make the claims true before telling anyone (0–4 weeks).** Fix auto-memory (C1), file tools (C2), and wire the web approvals to the backend; enforce the governance you advertise (an assertion/lint check on skill load — M2); fix or retire the 97.6% benchmark (C3/C4); ship a working install path. This is the founder's own "fix → benchmark → tell" rule, and it is non-negotiable — every other bet is fraudulent until it's done.

2. **Turn governance into a verifiable, owned substrate (the durable moat).** Ship G1 first: a **signed, append-only, exportable audit log** of every action + reason. Then G2: **provable blast-radius before a skill runs** — the structurally-correct, category-defining answer to ClawHavoc that only Hachi's typed `.og` format makes possible. This is the one thing a competitor can't copy in a month.

3. **Win the reliability/memory slice — because the thesis says it's what actually matters.** An agent that _reliably remembers you and finishes recurring tasks_ is table stakes Hermes already clears. Governance is moot if people stop using the product first. Add the goals/inbox surface (G4: consequence-boundary approvals) so autonomy feels like a capable coworker, not a firehose of prompts.

4. **Own the wedge; don't fight the giants where they're strong.** Target two segments the incumbents underserve: the **burned-by-OpenClaw self-hoster** who won't run a black box, and the **prosumer/small team** that needs hard cost caps + an audit trail. Concede coding to Claude Code/Cursor and instead **be the governed life/ops agent that also exposes an OpenAI-compatible endpoint** — so you're additive to the tools they already love, not a rival to them.

5. **Sharpen the `.og` skill-as-artifact story into the flagship, not a footnote.** Portable, diffable, scope-provable, versioned skills are Hachi's one genuinely novel bet. Lead with _"skills you can diff, audit, and prove the blast radius of"_ — not a token-savings percentage that dies on replication. This is the capability that makes G2 and G5 possible and is the real reason the format exists.
